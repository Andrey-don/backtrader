# Рекомендация: какую LLM использовать для обработки уроков

## Вывод: NotebookLM (Google)

**Почему NotebookLM, а не ChatGPT:**

| Критерий | NotebookLM | ChatGPT |
|----------|-----------|---------|
| Загрузка файлов (.txt + .jpg) | ✅ До 50 источников | ✅ Но ограничен по объёму |
| Контекстное окно | ✅ Очень большое (весь курс сразу) | ⚠️ Меньше |
| Работа с изображениями | ✅ Анализирует скриншоты | ✅ |
| Токены не тратятся повторно | ✅ Источники хранятся в проекте | ❌ Каждый чат заново |
| Генерация структурированного markdown | ✅ Через промпт | ✅ |
| Бесплатно | ✅ | ⚠️ GPT-4 платный |
| Граф знаний | ❌ | ❌ Нужен отдельный инструмент |

**Стратегия работы с NotebookLM:**
1. Создать **один проект** в NotebookLM
2. Загружать в него .txt транскрибации урок за уроком (можно несколько сразу)
3. Скриншоты прикладывать по мере надобности (для уточнения кода)
4. Использовать промпт ниже для каждого урока

## Как загружать скриншоты

Скриншоты пронумерованы (22.jpg, 23.jpg, ...). Не нужно загружать все — только те, на которых **виден код**. Рекомендуемая выборка: каждые 50–100 скриншотов просматривать первый и последний, чтобы понять, что там показано.

Загружать скриншоты имеет смысл когда:
- Транскрибация описывает код, но его сложно восстановить
- Есть упоминание «вот смотрите» без чёткого диктования кода
- Нужно уточнить структуру класса или отступы

## Финальный граф знаний (как строить)

После обработки всех уроков — граф строить через `/graphify` в Claude Code:
1. Скопировать все markdown-документы в одну папку
2. Запустить `/graphify` — это создаст HTML + JSON граф связей между концептами
3. Импортировать граф в Obsidian как визуализацию

Граф покажет связи: Cerebro → Strategy → Indicators → Orders → Optimization → Live-Trading
